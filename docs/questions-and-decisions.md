# 问题如何推动实验演化

项目最初关心跨权重 KV-cache 能否快速更新，随后逐渐转向 rollout 的采样成本和训练稳定性。这些问题互相关联，但每次实验只解决其中一部分。

| 最初的问题 | 我们做过的尝试 | 当前判断 | 接下来的判别实验 |
|---|---|---|---|
| 参数变化已知，能否便宜更新 KV？ | 增量 SVD、Fourier、仿射映射、全网络 JVP | 可近似性不等于在线速度；当前 JVP 比完整 prefill 更慢 | 计入拟合、存储和索引成本的真实端到端实现 |
| 浅层 E/V 小变化能否直接复用？ | 按层测量、固定旧 E 重算投影误差 | 形成浅层复用 E/V、重算 K 的方案，尚未做该方案在线长跑 | 多训练阶段、多 checkpoint 间隔、固定层数与自适应刷新对照 |
| 旧 attention 的热点能否用于重建？ | 旧 top100、新 top100 oracle、质量阈值及均值尾部 | 固定 top100 的截尾误差比热点变化更关键 | 真正稀疏 kernel、重建成本与完整回答质量一起测 |
| 1 对 7 错是否比 7 对 1 错更值得采样？ | 4+4、full8、race4、顺序至首次成功 | 采样分布和工作量都变了，当前方法不是无偏 GRPO 加速器 | 明确固定 token/时间预算，增加随机保留及期望修正对照 |
| 更少采样能否更快？ | 固定权重测速、pending 窗口和长跑 | 4+4 的阶段等待可抵消生成节省，质量也无单一排序 | 同权重成本测量与多种子质量比较分别进行 |
| RL 是否只提高第一次正确率？ | Base 与最终模型每题最多 100 次首中测试 | 首答和有限采样覆盖都提升，但总生成 token 增加 | 固定 token 预算、多种采样温度和新留出集 |
| 长度跃升是否就是失稳？ | 对齐首 token、长度、PPL、梯度与质量 | 早期可由模式选择驱动，并不伴随大梯度 | 在 full8 主线上重新做局部首 token 干预 |
| 是否某个题或 token 直接引爆？ | 异常题重采样、固定序列、精度和 token 干预 | 输入、模型状态和轨迹共同作用；尚未找到唯一触发题 | 预先指定风险题、多种子富集训练与匹配对照 |
| 老回答的负优势为何产生峰值？ | 同 batch 重放，完整/正负单独 TIS，均值与置换对照 | token 上的权重分配及负优势通道有作用 | 用原生完整状态重复，分开策略年龄与引擎失配 |
| 把梯度压低是否就修好了？ | 在线 TIS、同步 G8、晚期切换 TIS | 小梯度不保证更少异常输出；数学分数也不保证文本正常 | 同时看梯度、奖励、异常率、覆盖与成本 |
| 后期大梯度会不会自行回落？ | full8 第 650 轮完整恢复，计划续训至 850 | 正在运行，记录每次更新和真实 batch | 完成后统一比较前中后期，并定位最早峰值 |

## 保留的失败与反例

首版 race4 因底层请求标识不匹配，没有真正实现定向取消，因此不作为有效加速实验。Fourier 对带符号增量的留出预测效果弱，说明“灰度图看起来规整”不足以建立预测器。硬屏蔽 `@` 能去掉该字符，却没有恢复所选坏前缀的正确率与正常结束，说明症状并不等于机制。

我们也保留改变过原先解释的结果：后来按规范相对误差测量，K 的相邻变化可小于 V；8B full8 后期固定评测长度及机械重复下降时，梯度仍明显上升；在线 TIS 显著降低梯度，但选定端点的异常文本比例并未随之变好。这些反例限制了结论的适用范围，也决定了下一轮实验要控制什么。

## 当前优先顺序

先完成 full8 的 200 轮续训，保留逐次梯度、训练 batch、模型快照与完整恢复点。再围绕真实峰值做同输入、同损失系数、不同模型状态的复测。采样策略比较和缓存加速仍是独立研究线，不能用稳定性诊断的单个局部结果替代端到端验证。
