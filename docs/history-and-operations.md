# 长尾调度探索与实验工程问题

在后来的 8B 稳定性分析之前，我们已做过多种长尾调度长跑。它们解释了为什么最终把跨轮续写、组内停止和缓存重建拆成不同问题，也留下了必须保留的运行条件差异。

## 较早的 1.7B 长尾调度

以下旧设置主要使用 Qwen3-1.7B-Base、DeepMath 20,000 题、4,096 token 上限。目录记录的是各次运行当时的状态，不能直接与后来的 8B、40,299 题、8k 设置比较。

| 分支 | 如何处理没有完成的工作 | 历史记录中值得保留的事实 |
|---|---|---|
| [同步 DAPO](../history/20261022-base-deepmath-20k-24h/README.md) | 同步生成，等组完成再更新 | 约 24 小时完成 2340 轮，作为当时的基线 |
| [APRIL](../history/20261023-april-deepmath-20k-24h/README.md) | 保留生成的 token 前缀，跨更新续写 | 约 24 小时完成 2782 轮；不是浅层 E/V 近似复用实现 |
| [RollPacker 适配](../history/20261025-rollpacker-deepmath-20k-24h/README.md) | 跨更新只保留题目，当前策略下重新生成；短轮与 FIFO 长池配合 | 第一条轨迹在第 76 轮将短轮窗口从 112 改到 70，不能当固定配置全程对照 |
| [RollPacker 固定窗口重跑](../history/20261025-rollpacker-deepmath-70-fresh-24h/README.md) | 以窗口 70 重新开始独立训练 | 重启停机约 34 分钟被补回预算，时间口径与不补空档的其他 run 不同 |
| [TailSieve 适配](../history/20261026-tailsieve-deepmath-64-fresh-24h/README.md) | 长池与普通池并行，先纳入原长池有效组；跨更新只保留题目 | 约 24 小时完成 2465 轮；不能仅凭轮数判定质量与吞吐优劣 |
| [RollVerify 适配](../history/20261027-rollverify-deepmath-112-fresh-24h/README.md) | 按生成段和 token 校验可保留的旧前缀 | 第 8 轮因低接受率切换为同步 on-policy；最终 1806 轮不代表全程都在复用旧前缀 |

这些数字是原历史记录，不是统一硬件、同 batch、同 token 预算的新 benchmark。后来的 4+4 分组实验进一步改变设备数、批量、候选窗口及筛选规则，比较时必须回到[设置对照](setup-comparison.md)。

## CPU 调度、取消接口与实际执行

我们曾优化 CPU 判分、队列处理和候选窗口补充，并分别保留重新启动的实验。`cpuopt` 不是与旧 run 严格相同 batch 的新算法对照；部分短 run 因中断只有几十轮。完整历史曲线仍保留，但不会把中断片段拼成一个看似完整的长跑。

首版 race4 最关键的问题是请求标识与底层取消接口不匹配：逻辑上舍弃了组，但实际成功取消数为零。修复后的 race4v2 先检查真实取消再进入方法比较。这个教训也适用于缓存命中率：接口计数、逻辑复用与真实少做的工作应分别核对。[G-06](../experiments/evidence.md#g-06)

## GPU 故障与数据迁移

早期小模型长跑遇到 CUDA 执行错误和无法单卡复位的驱动状态，之后经授权重启。重启后基础计算、显存、PCIe 和集合通信检查通过，指定卡的 20 次生成及 sleep/wake 循环也没有复现故障；该恢复记录并没有建立故障的根因，更不能把系统退出解释成算法梯度失稳。

后续将约 **370.7 GB** 的实验归档直接在服务器之间传输，并核对完整文件 SHA256，避免本机空间不足。迁移保存的是实验材料；传输成功不等于每个 checkpoint 都仍有完整 optimizer 状态。

## Checkpoint 完整性决定了能回答什么

有些早期 checkpoint 后来仅剩数据状态或模型，没有 Adam/RNG；原 full8 最终记录到 662，但完整恢复点只保留 600、650。因此当前选择 650→850，明确标注重跑区间，不能声称从原 662 精确接续。

分析中还必须区别 FP32 master、导出 BF16 参数值和运行时算子精度；将 BF16 权重转成 FP32 张量不会恢复被舍入的参数。当前续训除了模型快照，也保留最近三个完整恢复点与实际 batch，以支持后续重放，而不只保留一张训练曲线。

工程记录的聚合出处见 [operations.json](../data/operations.json)。原服务器地址、设备标识和私有路径不属于研究结论，未纳入仓库。
